# 16 — SEO ON PAGE POR URL
--------------------------------------------------

Cada página indexable debe tener:

- URL estable;
- `<title>` único;
- meta description específica;
- H1 único;
- jerarquía H2/H3 coherente;
- contenido visible;
- canonical;
- Open Graph;
- imagen social;
- datos estructurados cuando corresponda;
- enlaces internos;
- breadcrumbs cuando aporten contexto;
- imágenes con alt descriptivo.

No utilizar títulos repetidos.

No utilizar H1 ocultos.

No generar texto exclusivamente para buscadores.

Google recomienda títulos claros, únicos y descriptivos y descripciones específicas por página. :contentReference[oaicite:3]{index=3}

--------------------------------------------------
# 17 — URLS
--------------------------------------------------

Usar URLs limpias.

Correcto:

/mercado-de-pases
/como-jugar
/carrera-del-dt
/guia-4-3-3

Evitar:

/page?id=23
/post?article=92831
/category?id=4

No introducir parámetros innecesarios.

--------------------------------------------------
# 18 — CANONICAL
--------------------------------------------------

Cada página indexable debe declarar su URL canonical preferida.

Ejemplo:

<link
rel="canonical"
href="https://vestuario.com.ar/mercado-de-pases"
/>

Resolver explícitamente:

- www vs non-www;
- HTTP vs HTTPS;
- trailing slash;
- parámetros;
- páginas duplicadas.

La canonical debe ser consistente con redirects, sitemap y arquitectura. Google considera la canonicalización una señal de preferencia, no una garantía absoluta. :contentReference[oaicite:4]{index=4}

--------------------------------------------------
# 19 — HTTPS
--------------------------------------------------

Forzar:

HTTP → HTTPS

Elegir una versión canónica del host.

No permitir:

http://vestuario.com.ar
https://vestuario.com.ar
http://www.vestuario.com.ar
https://www.vestuario.com.ar

como sitios independientes.

Debe existir una única versión principal.

--------------------------------------------------
# 20 — ROBOTS.TXT
--------------------------------------------------

Crear:

/robots.txt

Debe permitir el rastreo del contenido público.

Bloquear únicamente áreas que realmente no deban rastrearse.

Ejemplo conceptual:

User-agent: *
Allow: /
Disallow: /app/
Disallow: /api/
Disallow: /admin/

Sitemap:
https://vestuario.com.ar/sitemap.xml

IMPORTANTE:

robots.txt controla rastreo, no sustituye `noindex`.

El archivo debe estar en la raíz del host. :contentReference[oaicite:5]{index=5}

--------------------------------------------------
# 21 — XML SITEMAP
--------------------------------------------------

Crear:

/sitemap.xml

Incluir solamente URLs públicas que realmente se quieran indexar.

No incluir:

- login;
- dashboard;
- endpoints;
- URLs temporales;
- filtros duplicados;
- páginas con noindex;
- URLs canonicalizadas hacia otra página.

Utilizar URLs absolutas.

El sitemap ayuda al descubrimiento, pero no garantiza indexación ni ranking. :contentReference[oaicite:6]{index=6}

Si el número de URLs creciera considerablemente:

/sitemap.xml
→ sitemap-pages.xml
→ sitemap-guides.xml
→ sitemap-news.xml
etc.
